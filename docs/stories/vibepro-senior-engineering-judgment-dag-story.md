# Story: 佐藤の思考順序を再現するシニアエンジニア判断DAG

## 背景

VibeProには、シニアエンジニアが見るべき判断軸をDAGとして表す設計資産があった。しかし、軸の内容が
妥当でも、問題設定を疑う前に分類し、到達していない軸まで一律に集約すると、本来の判断順序と異なる。
その結果、不要な枝の不足証拠が残り、未知がブロックへ変換され、現実の意思決定よりチェックリスト消化が
優先される。

## ユーザー価値

VibeProを使うシニアエンジニアとして、違和感、ゴール、問題設定、仮説、予測、反証、制約、選択肢を
一つの追跡可能な判断DAGに残し、必要な判断軸だけを適切な順番で評価したい。これにより、自分の思考の
強みを維持しながら、説明力の高い誤仮説や目的による証拠選択の偏りを検出したい。

## 受け入れ基準

- [x] 判断軸の評価より前に、ゴールと問題設定そのものの妥当性が評価される
- [x] 問題設定が不適切なら下流の軸を評価せず、再設定を推薦する
- [x] 必要と判断された軸だけが到達可能になり、未到達の軸は全体判断に影響しない
- [x] 各仮説について、予測と、その予測を支持・反証・識別不能とする証拠を追跡できる
- [x] 反証された仮説の枝は閉じ、その枝専用の不足証拠を残さない
- [x] 証拠不足を自動的な合格または失敗にせず、追加調査・安全な先送り・人間判断を区別する
- [x] 影響範囲、可逆性、重大度に応じて軽量判断と深い判断を使い分ける
- [x] 制約違反の選択肢を除外し、残った選択肢と残存リスクから説明可能な推薦を作る
- [x] 一回の判断は非循環で、新しい証拠による更新は親実行を参照する新しい判断として残る
- [x] 判断結果はレビュー可能な助言であり、PR作成、マージ、デプロイを自動で許可または禁止しない

## 成功の見え方

- 同じ入力から同じ到達枝と推薦が得られる
- 推薦から、使われた観測・仮説・証拠・制約へ逆向きに辿れる
- 「なぜこの軸を見なかったか」と「なぜこの仮説を捨てたか」の両方を説明できる
- 次の人間判断または追加調査が、一般論ではなく未解決の仮説に結び付いている
