# 基本概念

VibeProは、変更の意図、実装への参照、検証証跡、人によるレビューを一緒に読み返せるようにします。

| 概念 | 役割 |
| --- | --- |
| Story | なぜ作業を行うのか、どの利用者・運用者の結果を変えるのか |
| Spec | 検証可能な受け入れ条件と不変条件を、Storyや関連ファイルへ結び付ける |
| 検証 | 実行したコマンドまたは外部結果を、変更の証跡として記録する |
| レビュー | 確認対象、要約、問題点を残す軽量なレビュー記録 |
| PR要約 | `.vibepro/pr/<story-id>/` に保存する機械可読の引き渡し情報とPR本文 |
| Impact Context | どこを読むべきかを決める任意のGraphify・コード構造の文脈 |
| Task計画 | TLが作る技術分割。Task、依存種別、接続契約、割当、統合順、計画版、必要な証跡を持つ |
| 実行記録 | 外部hostが持つセッション、worktree、占有、試行、チェックポイント、検証、統合の記録 |
| TLの計画判断 | Storyをどう分け、どう調整するかという技術判断。プロダクト優先順位やmerge・deploy権限は持たない |

これらは通常のGitHub PRレビューを支える記録であり、プロダクト上の意味、意味的な正しさ、リリースの安全性、マージ権限を自動で決めるものではありません。ファイルやアンカーの存在確認はトレーサビリティを示しますが、振る舞いの正しさを証明しません。現在の流れは[制御ループ](/ja/guide/control-loop)、廃止機能を含む境界は[機能マップ](/ja/guide/feature-map)を参照してください。

Task計画は版付きの計画artifactであり、実行台帳ではありません。外部実行側が守る作業範囲と
契約を記録します。前提依存を解除できるのは、計画版、成果物revision、証拠参照が一致する
観測がある場合だけです。Taskのstatusだけでは解除できません。接続契約の合意と実装milestoneの
検証は別の観測として扱うため、契約を決めてから実装を並行できます。

TLはこの技術計画面を担当します。既存Taskへの分割、`prerequisite`・`interface`・`overlap`の
依存分類、接続契約、割当計画、統合順、再計画を判断します。Codex親などの外部hostは、
セッション配布、worktree、占有、再試行、復旧、実行進捗を担当します。VibeProの計画と観測は
レディネスを示せますが、merge・deploy権限を与えません。Brainbase接続時は参照と進捗を投影
できますが、第二のTask正本を作りません。
