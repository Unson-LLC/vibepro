# VibeProの事例

機能の説明だけでは、VibeProを何に使えるのか分かりにくい。ここでは、実際の開発記録から「そのまま進めると困ったこと」と「どこで止めたか」を抜き出しました。

## 実運用の匿名事例

### [根拠が足りない回答を、そのまま出さない](./evidence-gated-answer)

必要な一次根拠を取得できないとき、もっともらしい回答を返さず保留にする条件を実装した事例です。

### [処理が終わる前に、失敗件数で判断させない](./stable-completion-decision)

一括処理の途中で変わる件数を判断材料にせず、全件の状態が確定してから一度だけ判断できるようにしました。

### [更新対象が途中で変わっても、担当範囲をずらさない](./stable-batch-window)

更新中に対象データが増減しても、同じ対象を重複処理したり取りこぼしたりしない実行枠へ変えた事例です。

### [再起動しても、実行結果を置き去りにしない](./restart-safe-delivery)

チャットから始めた長時間処理が途中で再起動しても、結果を保存し、復旧後に届けられるようにしました。

## 公開記録をたどれる事例

### [誤ったリリースを公開前に止めた2時間](./release-safety)

プレリリースの分類不具合と、最初の修正案に残った回帰リスクを、公開前に解消した記録です。この事例は公開PRと実行結果までたどれます。

## 匿名化について

匿名事例は、社名、製品名、業種、日付、リポジトリ、PR、固有の件数を公開していません。Git、Story、Spec、テスト、実行記録で確認できた内容を基にしていますが、関係者を推測できる原典との対応表も掲載しません。

確認できた実装や検証と、まだ確認できていない顧客成果は各ページで分けています。
