# VibePro Senior Engineering Judgment Frame

## 目的

VibeProのシニアエンジニア判断は、一般的なチェックリストの網羅率ではなく、限られた時間で
現実に合う因果モデルを作り、誤った問題設定や不要な調査を早く捨て、レビュー可能な意思決定へ
到達する能力を支援する。

このFrameが取り込む思考アルゴリズムは、次の高速ループである。

> 違和感を検知する → 事実を分ける → ゴールを固定する → 問題設定を疑う → 原因仮説を作る →
> 仮説から予測を導く → 識別力のある証拠を当てる → 反証または更新する → 制約で選択肢を削る → 判断する

## 中心原則

1. **問題をそのまま受け取らない**
   既存のStory、Issue、依頼文も仮説である。下流の設計判断より先に、ゴールと問題設定の妥当性を確認する。
2. **同じ判断軸を、必要な順番で使う**
   セキュリティ、データ、実行経路、UX、性能、変更容易性、リリース運用などの軸自体を弱めない。
   ただし、全軸を常に評価せず、到達可能になった軸だけを評価する。
3. **説明力ではなく識別力を求める**
   仮説をもっともらしく説明する証拠ではなく、仮説が正しい場合と誤っている場合を分ける証拠を優先する。
4. **反証を成功として扱う**
   仮説が反証された枝は閉じる。反証後も、その仮説向けの不足チェックを残してはならない。
5. **未知を合格にも失敗にも変換しない**
   証拠不足は `inconclusive` であり、影響と可逆性に応じて追加調査、safe-to-defer、人間判断へ分岐する。
6. **深く考える価値を先に判断する**
   影響が局所的で容易に戻せる変更と、不可逆・広範囲な変更へ同じ推論コストを使わない。
7. **一つの実行は非循環、学習は実行間で循環する**
   一回の判断はDAGとして完結させる。新しい事実による更新は、親実行を参照する新しいDAG実行として残す。
8. **VibeProは判断を支援し、権限を奪わない**
   出力は説明可能な推薦である。マージ、承認、デプロイの最終権限は人間、CI、リポジトリ規則に残す。

## 良い判断の定義

良い判断とは、結果が偶然正しかった判断ではなく、次を第三者が追跡できる判断である。

- 何を達成しようとしていたか
- どの観測から違和感を持ったか
- 問題設定をなぜ妥当または不適切と考えたか
- どの仮説を、どの予測と証拠で反証・支持したか
- どの制約で選択肢を除外したか
- 何が未確定で、誰が最終判断するか
- 前回の判断から何が変わったか

## 非目標

- 全変更に重い分析を強制すること
- 自然言語の単語一致だけでリスク軸を自動確定すること
- 証拠ファイルの存在だけで仮説を成立させること
- 全判断軸のANDでPR作成を止めること
- 人間やCIに代わって「安全」「マージ可能」を認定すること
