# 送信先照合の補強

## Story
利用者が指定したリポジトリ以外へ、同じpushが同時送信されないようにする。

## 最小Spec
- remoteに複数のpush URLがある場合、PR作成を送信前に停止する。
- 計画後にpush URLが追加された場合も実行直前の再確認で停止する。
- 単一URLの既存経路は維持する。
- エラーにURLや認証情報を含めない。

## 期待する変更先の受け渡し

- PR作成には `--repo owner/name` を必須とし、remoteから変更先を推測しない。
- PR作成のpush子プロセスには、その指定を `VIBEPRO_EXPECTED_REPOSITORY` として渡す。
- pre-pushフックはGitが渡す実際のURL（第2引数）と同環境変数を、作業ブランチを含む全pushで照合する。未指定、不一致、照合CLI不在は停止する。
- 既存の準備確認用bypassは、この送信先照合を省略しない。

## 適用範囲と未完了

これはGitHub向けの送信先照合。他のGitホストには未対応。インストール済みのフックは自動更新されない。期待する変更先は呼び出し側で判断し、明示して渡す。
環境変数は判断の受け渡しであり、権限の証明ではない。利用者やエージェントが期待先を誤指定した場合、フックを無効化した場合や `--no-verify` を使用した場合は防げない。内容・履歴の公開可否をこの照合だけで判断しない。
既存の別フックを上書きせず、導入時には連結と実際の起動を別途検証する。再発防止全体の完了とはしない。
