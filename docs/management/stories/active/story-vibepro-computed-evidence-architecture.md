# 証跡を「AIが書くもの」から「実行が残すもの」へ移し、AIの誠実さに依存しない出荷構造を作る

## Background（実測。推測ではない）

先行 Story（enumeration coverage gate、ブランチ `claude/musing-lamport-3603be`）で、
gate stage の独立レビューを6ラウンド実施した。全 findings は
`.vibepro/reviews/story-vibepro-enumeration-coverage-gate/gate/history/` に記録されている。

結果を主張の種別で分けると、成績は完全に二分された。

**機械が再計算した主張: 6戦6勝。**
実装エージェントが宣言した識別子の出現数を gate 自身が宣言範囲を再走査して照合する機構は、
6ラウンドを通じて一度も破られなかった。水増しした count、重複パスによる膨張、
狭すぎる範囲の申告は、すべて再計算との不一致として機械的に検出された。
round 6 のレビュアーは、公開された6件の count すべてを2種類の grep で独立再現し
「変更の最も強い部分」と評価した。

**実装エージェントが自由文で書いた主張: 6戦6敗。**

| Round | 自由文の主張 | 実態 |
|---|---|---|
| 2 | 「28 assertions が両方の blocking predicate をカバー」 | どちらも一切テストされていなかった |
| 3 | 「実測に基づき修正」 | 他エージェントの測定を未検証で転記 |
| 4 | 「5語彙すべて揃えた」 | 実際は7、のちに9、最終的に12面 |
| 5 | 「binary 除外は record される」 | consumer のみ配線、producer 未実装で常に空 |
| 6 | 「every classifier を振る舞いで検証」 | 12面中8面。5面同時 revert でも 268 テストが green |
| 6 | （申告なし） | レビュー実行中にツリーを変更。レビュアーが検出、自己申告なし |

さらに手続き面では、実装エージェントが gate の判定基準・証跡の記録・予算の増額
（自己承認2回）を同時に担っており、止める仕組みの設計権と緩める権限が
止められる側に集中していた。停止条件はエージェントの作文（amendment_reason）に
依存し、コードでは発火しなかった。

レビュアー側も無謬ではなかった。round 2 の「spec clause が存在しない」は誤りで
実装側の照合により棄却され、round 4 の grep 測定は誤りのまま実装側が無検証で
取り込んだ。レビューを信頼可能にしたのは形式ではなく、**別主体による再現の連鎖**が
あった箇所だけである。round 6 の mutation testing（変更サイトを1つずつ戻して
テストが落ちるか確認する）が未知の欠陥を全て発見できたのは、レビュアーの想像力
ではなく、**探索空間が diff から機械的に導出できた**からである。

## 学び（このStoryの前提）

1. **証跡の信頼性は書き手の誠実さではなく、判定の実行主体で決まる。**
   実装エージェントが計算しない判定だけが破られなかった。
2. **反証可能に書かれた意図は安価だが不十分。** 6ラウンドの findings のほぼ全ては
   受け入れ条件が覆っていない領域で出た。意図の記述は入口条件にすぎない。
3. **探索空間を artifacts から導出できる検査だけが、未知の欠陥に届く。**
   想像で列挙した反証（「この N 通りで壊してみた」）は N の選び方に盲点が残る。
4. **再実行で消える状態（stale）と消えてはならない記録（violation）を
   同じ語彙で扱うと、違反は stale として洗い流される。** 実際に洗い流された。
5. **人間の裁定は per-change ではなくエピソードで発生するのが正しい頻度。**
   26コミットに2回。直すべきは頻度ではなく、裁定材料がエージェントの
   自己申告文に依存していた点である。

## あるべき姿（3層）

**層1: 計算層 — 証跡は実行の排気であり、作文ではない。**
エージェントが書けるのは手続きの宣言のみ（何をどの範囲でどう測るか）。
数値・pass/fail・実行時刻・head sha はシステムが計算して記録し、
エージェントの入力を経由しない。

**層2: 導出層 — 検査対象は artifacts から機械導出する。**
diff の変更サイト → mutation 対象。共有定数 → 全消費者の列挙。
受け入れ条件 → 反証条件。レビューは白紙からの探索ではなく
「導出済みチェックリストの実行 + 残余の探索」になり、レビュアーの発見には
再現手順を義務付け、別主体の再現を経て確定する。

**層3: 裁定層 — 人間はエピソードで裁く。**
停止条件（予算超過・同一クラス再発 N 回・レビュー面のレビュー中変更）は
コードで発火し、エージェントの申告に依存しない。人間に届く裁定材料は
エージェントの説明文ではなく、記録された事実から生成された選択肢である。

**権限分離:**

| 役割 | 現状 | あるべき |
|---|---|---|
| 実装 | エージェント | エージェント |
| 判定の実行 | 一部エージェント | システムのみ |
| 判定基準の変更 | エージェント | 人間、または別セッション + decision record |
| 予算・停止条件の変更 | エージェントの自己承認 | 人間のみ。コードで強制 |
| 違反の記録 | レビュアーの偶然の発見 | append-only。再実行で消えない |

## User Story

**As a** AI エージェントに実装を任せるリポジトリ所有者
**I want** エージェントの自由文申告が judgement に一切入らず、判定はシステムの
計算と導出された検査だけで決まり、人間の裁定は停止条件の発火時だけ求められる構造
**So that** エージェントが誠実かどうかを監視するコストを払わずに、
任せられる変更量を増やせる

## Acceptance Criteria（親レベルの不変条件。子 Story が実装する）

- [ ] CEA-S-1: 検証コマンドの実行結果（exit code・テスト数・計数値）が、実装エージェント
      の入力を経由せずに証跡 artifact へ記録される経路が存在する。エージェントが同じ
      フィールドに任意値を書いた場合、記録は拒否されるか、計算値で上書きされ差分が残る。
- [ ] CEA-S-2: 網羅範囲の主張について、実測値 N はシステムが計算して埋め、エージェントが
      宣言できるのは識別子と範囲のみになる。エージェントが N を自書きした証跡と
      システムが計算した証跡が artifact 上で区別できる。
- [ ] CEA-S-3: レビューの lifecycle が close 時点の head も記録し、start 時点と異なる場合は
      「レビュー面のレビュー中変更」として append-only の違反記録が残る。この記録は
      レビューの再実行では消えない。
- [ ] CEA-S-4: 予算・停止条件の Story 別 override は、エージェント自身のセッションからは
      書き込めず、accepted な decision record（人間の承認を示す）を伴う場合のみ有効になる。
- [ ] CEA-S-5: レビュー依頼に、diff から機械導出された mutation 対象一覧（変更サイトごとの
      revert 検査）が添付され、レビュー結果はその実行結果を含む。
- [ ] CEA-S-6: 同一クラスの high finding が N ラウンド連続で発生した場合、コードが検出して
      以後の review authorize を停止し、人間の裁定を要求する。エージェントの申告文への
      依存なしに発火する。

## Decomposition（子 Story 候補・優先順）

1. **violation ledger**（CEA-S-3）: stale と violation の型分離。最小で最初に効く。
2. **computed enumeration**（CEA-S-2）: 先行 gate の N 自書きを廃止する後継。
3. **runner-direct evidence**（CEA-S-1）: テスト実行結果の直接記録。
4. **owner-gated budget**（CEA-S-4）: 予算 override の decision record 必須化。
5. **derived mutation checklist**（CEA-S-5）: レビュー依頼への mutation 一覧添付。
6. **class-recurrence circuit breaker**（CEA-S-6）: 停止条件のコード化。

## Non Goals

- 「作るべきものが正しいか」（製品意図の妥当性）の自動判定。これは人間の領域として残す。
- 既存の記録済み証跡 artifact の遡及的無効化。
- 人間の裁定回数をゼロにすること。目標はエピソード化と裁定材料の脱・自己申告であり、
  ゼロ化ではない。
- 先行 enumeration gate ブランチの処遇の決定（別途、所有者の裁定事項）。

## 残余（明示しておく）

この構造でも消えないものが2つある。第一に、層2の導出がまだ発明されていない検査領域では
当面レビュアーの自由文探索が残る（ただしその発見も再現の連鎖を通す）。第二に、
意図そのものの妥当性は計算に落ちない。この2つを「不足」ではなく「人間の仕事の定義」
として扱うのが本 Story の立場である。
