# 旧形式Storyタスクの互換境界

## 判断

`buildStoryTaskState` が既存 `tasks.json` を現行の内部タスク形へ取り込む境界で、配列フィールドを正規化する。描画側だけに任意値分岐を足さず、以降の生成・描画処理が単一の内部契約を利用できる状態にする。

## データフロー

1. 既存 `tasks.json` を読む。
2. 完了済みタスクを識別子と状態を保ったまま引き継ぐ。
3. 任意だった旧フィールドを現行の既定値へ正規化する。
4. 正規化済み状態から `tasks.json` とMarkdownを生成する。

## 互換性と境界

- `read_first_files` 欠落は空配列として扱う。
- 既存の未知フィールド、識別子、status、finding参照は保持する。
- Graphifyの取込順、診断finding生成、タスク完了判定は変更しない。
- 破損した非配列値まで暗黙に成功へ丸めず、後方互換として確認できた「欠落」だけを対象にする。

## 検証

- 旧形式完了タスクの状態保持を単体テストする。
- その状態をMarkdown描画まで通し、例外が発生しないことと読込対象なしの表示が `Read first: -` になることを確認する。
- 公開packageを実fixtureへ導入し、`story diagnose --run-graphify` の成果物をreadbackする。
