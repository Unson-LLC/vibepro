# アーキテクチャ

## 判断

日本語の公開事例を、一覧1ページと匿名事例4ページに分ける。既存のリリース安全事例は残し、一覧から5件すべてへ移動できるようにする。日本語ナビゲーションの「事例」は、個別ページではなく一覧を指す。

## 公開面

| 役割 | URL | ファイル |
|---|---|---|
| 事例一覧 | `/ja/cases/` | `docs/ja/cases/index.md` |
| 根拠不足の回答を止める | `/ja/cases/evidence-gated-answer` | `docs/ja/cases/evidence-gated-answer.md` |
| 処理完了前の判断を止める | `/ja/cases/stable-completion-decision` | `docs/ja/cases/stable-completion-decision.md` |
| 更新対象のずれを止める | `/ja/cases/stable-batch-window` | `docs/ja/cases/stable-batch-window.md` |
| 再起動後も結果を届ける | `/ja/cases/restart-safe-delivery` | `docs/ja/cases/restart-safe-delivery.md` |

既存の `/ja/cases/release-safety` はURLと既存本文を維持し、事例一覧へ戻るリンクだけを追加する。英語ナビゲーションは変更しない。VitePressの言語切替が未生成の `/cases/**` を指さないよう、同じスラッグに日本語版への案内ページを置く。英語面に匿名事例本文は複製しない。

## 匿名化の境界

公開ページには、原典の社名、製品名、リポジトリ名、PR番号、URL、コミットSHA、日付、担当者名を置かない。業種や運用主体を絞り込める固有の件数、時刻、画面名も一般化する。

残すのは次の情報に限る。

- 利用者が直面していた失敗
- 実装で変えた判断条件または復旧条件
- Git、テスト、PR履歴で確認できた範囲
- VibeProの工程が寄与した範囲
- 売上や工数、利用者への効果など、未確認の範囲

原典との対応表は公開リポジトリに保存しない。公開後に原典を明かす場合は、関係者の許可を得た別のStoryで扱う。

## 主張の境界

「導入効果が出た」「品質が向上した」と一般化しない。各ページは、実装、テスト、マージ、または本番反映のうち確認できた段階を明記する。顧客満足度、売上、工数削減、不具合削減率は、計測記録がない限り未確認と書く。

VibeProが問題を単独で発見したとは書かない。人やエージェントが見つけた問題をStory、Architecture、Spec、テスト、Gateへつなぎ、変更理由と確認条件を残したことを寄与範囲とする。

## 導線

事例一覧は各ページの「起きていたこと」と「変えたこと」を短く載せる。詳細ページの末尾から一覧へ戻れるようにする。既存のリリース安全事例も一覧へ含め、公開事例が一か所で見つかる状態にする。日本語ページの言語切替先には英語の案内ページを置き、日本語版と英語一覧へのリンクを返す。

## 検証

専用のNode.jsテストで、5件への導線、匿名ページの必須見出し、匿名化禁止語、原典URLの不在、成果を一般化しない記述、言語切替先となる英語案内ページを固定する。VitePressの公開ビルドで、日本語の一覧と5件、英語案内の一覧と5件が生成されることを確認する。

## 互換性とロールバック

CLI、Gate、レビュー、PR作成、公開処理には触れない。問題がある場合は一覧、匿名事例4ページ、英語案内ページ、ナビゲーション変更、専用テストを同時に戻す。既存のリリース安全事例とURLは残る。
