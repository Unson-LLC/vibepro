# アーキテクチャ

## 判断

日本語の公開事例を `docs/ja/cases/release-safety.md` に置き、日本語ナビゲーションの「事例」から直接到達できるようにする。内部向けの `docs/marketing/**` はVitePressの公開対象外であるため使わない。

## 情報の境界

ページ内の情報を次の二層に分ける。

- 確認できた事実: PR #450から#452、公開ワークフロー、公開バージョン、記録時刻。公開リンクだけで追跡できない作業スレッド由来の時刻とレビュー経緯は、その出所と計測境界を本文に書く。
- この事例からの解釈: VibeProの工程が、公開停止の判断、修正内容、検証、レビューの文脈を追跡できる状態にしたこと。

VibeProが不具合を単独で自動検出したとは書かない。今回の一例から不具合削減率、開発速度、投資対効果を一般化しない。PR #451は過去のプレリリースを再分類していないため、`beta.6`と今後処理するReleaseに範囲を限定する。

## 公開導線

- 公開URL: `/ja/cases/release-safety`
- 日本語ナビゲーション: `事例`
- 英語ナビゲーションと既存URLは変更しない。
- 根拠はGitHub上のPRとActions実行へ直接リンクする。

## 検証

専用のNode.jsテストで、ページと導線、根拠リンク、公開バージョン、所要時間、誇張防止表現を固定する。VitePressの公開ビルドで、新しいURLを含む全体の生成を確認する。

## 互換性とロールバック

CLI、検証、レビュー、PR作成、リリース処理には触れない。問題がある場合は、新規ページ、ナビゲーション項目、専用テストを同時に戻す。既存ページと既存URLはそのまま残る。
